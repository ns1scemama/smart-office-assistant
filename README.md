# עוזר מסמכים חכם למשרד (Smart Office Document Assistant)

אפליקציה שעוטפת אוטומציית n8n שקוראת מסמכים משרדיים, מחלצת מהם מידע עסקי
באמצעות AI, רושמת שורה ביומן, ומתריעה לצוות. האפליקציה היא הפנים של המערכת.
n8n הוא המנוע.

**מה זה עושה בפועל:** עובד משרד גורר מסמך למסך, רואה מצב "מעבד", וכעבור כמה
שניות מקבל על המסך את השדות שחולצו: סוג מסמך, שולח, תקציר, פעולה נדרשת, מועד
יעד, דחיפות, מחלקה. המסמך מופיע גם בלוח מסמכים שניתן לחפש ולסנן בו, ושם אפשר
לפתוח אותו ולסמן "נבדק".

## ארכיטקטורה

שלוש שכבות עם הפרדת אחריות מוחלטת:

```
┌──────────────────────────────────────────────────────────┐
│  שכבת אפליקציה  (חלק 2)                                   │
│  React + Vite  ·  3 מסכים: העלאה, לוח מסמכים, פירוט        │
│  ↓ קורא ל־/api/*                                          │
│  שרת Express דק  ·  מוסיף את הסוד בצד השרת בלבד           │
└──────────────────────────────────────────────────────────┘
                            ↓ HTTPS + x-api-key
┌──────────────────────────────────────────────────────────┐
│  שכבת אוטומציה  (n8n)                                     │
│  Workflow A: POST /process-document                       │
│  Workflow B: GET  /documents                              │
│  Workflow C: POST /review                                 │
│  Part 1:     Google Drive Trigger (תיקיית Incoming)       │
│         ↓ כולם קוראים לאותה תת־זרימה                       │
│  SOA - Shared Processing                                  │
│  חילוץ טקסט → Claude → Sheets → IF דחיפות → Gmail         │
└──────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────┐
│  שכבת שירותים                                             │
│  Google Drive  ·  Google Sheets  ·  Gmail  ·  Claude API  │
└──────────────────────────────────────────────────────────┘
```

**הכלל שמגדיר את הפרויקט:** האפליקציה לא מממשת מחדש שום לוגיקה עסקית. היא לא
קוראת למודל AI, לא כותבת ל־Sheets, לא שולחת מייל, ולא מחליטה מה נחשב דחוף.
היא אוספת קלט, קוראת ל־n8n, ומציגה את מה שחזר.

## הרצה

```bash
npm install
npm run dev
```

**זה עובד מיד, בלי שום הגדרה.** בהיעדר `.env` השרת עולה במצב mock ומגיש נתוני
דוגמה, כך שאפשר לראות את כל הממשק לפני שמחברים שום דבר. כדי לעבוד מול n8n
אמיתי, העתק את `.env.example` ל-`.env` ומלא את הערכים.

בדיקת שלוש נקודות הקצה בפקודה אחת:

```bash
npm run smoke
```

הפקודה מריצה יחד את שרת ה־Express (פורט 3001) ואת Vite (פורט 5173).
פתח `http://localhost:5173`.

### משתני סביבה

כל הערכים ב־`.env.example`. הקובץ `.env` עצמו ב־gitignore ולא נכנס ל־repo.

| משתנה | תפקיד |
|---|---|
| `N8N_BASE_URL` | כתובת הבסיס של ה־webhooks ב־n8n |
| `N8N_PROCESS_PATH` / `N8N_DOCUMENTS_PATH` / `N8N_REVIEW_PATH` | שלוש נקודות הקצה |
| `N8N_SECRET` | הסוד המשותף שנשלח בכותרת `x-api-key` |
| `REQUEST_TIMEOUT_MS` | 90,000. חילוץ AI ממסמך גדול לוקח עד דקה |
| `MAX_FILE_MB` | 10 |
| `VITE_USE_MOCK` | `false` לעבודה מול n8n אמיתי. כל ערך אחר, כולל היעדר קובץ, נופל למצב mock |

## נקודות הקצה

הפורמט המדויק של כל בקשה ותשובה נמצא ב־[CONTRACT.md](CONTRACT.md).

| נקודת קצה | מה היא עושה |
|---|---|
| `POST /webhook/process-document` | מקבלת קובץ ב־base64, מעלה ל־Drive, מריצה את העיבוד, מחזירה את שבעת השדות |
| `GET /webhook/documents` | מחזירה את כל שורות היומן כמערך JSON |
| `POST /webhook/review` | מעדכנת סטטוס, מבצע הבדיקה והערה לפי `document_id`. מחזירה 404 אם אין שורה תואמת |

כולן מוגנות באימות כותרת (`x-api-key`). בקשה בלי מפתח מקבלת 403.

### מיפוי שגיאות לחוויית משתמש

| קוד | מה המשתמש רואה |
|---|---|
| `UNSUPPORTED_FILE_TYPE` | "ניתן להעלות רק קבצי PDF, DOCX או TXT". נחסם באפליקציה עוד לפני שליחה |
| `EMPTY_DOCUMENT` | "לא נמצא טקסט קריא במסמך הזה" |
| `EXTRACTION_FAILED` | "עיבוד המסמך נכשל" + כפתור נסה שוב, הקובץ נשמר בטופס |
| `UNAUTHORIZED` | "בעיית הגדרות מערכת: מפתח הגישה שגוי או חסר" |
| `NOT_FOUND` | "המסמך לא נמצא ביומן" |
| `TIMEOUT` | "העיבוד ארך זמן רב מדי" אחרי 90 שניות |
| `UPSTREAM_UNREACHABLE` | "לא ניתן להתחבר למערכת האוטומציה כרגע" |

## מקור האמת

ל־Google Sheet יש 14 עמודות והוא **מקור האמת היחיד** של הלוח. לאפליקציה אין
בסיס נתונים משלה, וזה מכוון: אפשר למחוק את האפליקציה ולבנות אותה מחדש בלי
לגעת בהרשאה אחת של גוגל, כי ה־credentials לא עוזבים את n8n.

## Known limitations

1. **פולינג של Google Drive Trigger תלוי בכך שמופע ה־n8n ער.** הזרימה נרשמת
   בעת הפעלת השירות. הפעלת workflow דרך ה־API בלבד לא רושמת את הפולר בתהליך
   הרץ, ונדרשה הפעלה מחדש של השירות כדי שהטריגר יתחיל לעבוד. מסמך שנכנס בזמן
   שהשירות היה כבוי לא ייקלט רטרואקטיבית.
2. **DOCX לא נתמך במקור על ידי צומת Extract From File.** הפתרון: העתקה זמנית
   של הקובץ כ־Google Doc, ייצוא כטקסט, ומחיקת ההעתק. זו הסיבה שבתת־הזרימה יש
   שלושה ענפי חילוץ ולא צומת אחד.
3. **PDF בעברית מחזיר טקסט עם מספרים במיקום שגוי** בגלל אלגוריתם ה־bidi. המלל
   עצמו קריא לחלוטין והמודל מבין אותו נכון, אבל טקסט גולמי שנשלף מ־PDF עברי לא
   נראה תקין לעין אנושית.
4. **הסוד נשלח מהדפדפן רק דרך שרת הביניים.** אם מריצים את הממשק בלי השרת, אין
   דרך לקרוא ל־n8n. זו החלטה מכוונת, לא באג.
5. **אין הרשאות ותפקידים.** כל מי שנכנס לאפליקציה יכול לסמן מסמך כנבדק.
6. **סימון Needs Review הוא היוריסטיקה, לא ודאות.** מסמך שבו שניים או יותר
   מארבעת שדות המפתח חזרו ריקים מסומן אוטומטית כדורש בדיקה. מסמך מעורפל שבכל
   זאת הצליח למלא שלושה שדות יסומן Processed, ואדם עדיין צריך לעבור עליו.

## סקירה אנושית

האוטומציה עוזרת לעובדים לקרוא ולארגן מסמכים מהר יותר. אדם עדיין צריך לעבור על
מסמכים רגישים, משפטיים, פיננסיים או לא ברורים לפני קבלת החלטה חשובה. המערכת
מציגה "Not found" ו־"No action found" כפי שהם, ולעולם לא ממציאה מידע חסר.
